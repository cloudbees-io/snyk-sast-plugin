= CloudBees action: Scan with Snyk Code (SAST)

Use this action to scan application source code for security vulnerabilities with the Snyk Code scanner.
You can also use the action output as a quality gate for the next step or job in your workflow.

Snyk Code is a developer-first Static Application Security Testing (SAST) solution that scans your source code for security vulnerabilities and quality issues.

Add a Snyk Code scan to your workflows in CloudBees platform to:

* Detect security vulnerabilities in your application source code before deployment.
* Identify potential security issues in multiple programming languages including JavaScript, Python, Java, Go, PHP, Ruby, and more.
* Gain insight into code security risks and how to fix issues.
* Ensure compliance with security best practices and industry standards.
* Shift security left by catching issues early in the development lifecycle.

CloudBees platform enables you to run a Snyk Code scan either implicitly or explicitly.

== Explicit and implicit scan types

An implicit scan is automatically triggered, and an explicit scan is one you configure to be invoked in a step of your workflow.
To learn more about the differences between explicit and implicit scans, refer to link:https://docs.cloudbees.com/docs/cloudbees-platform/latest/actions#security[Security scan actions].

To set up implicit scanning, refer to link:https://docs.cloudbees.com/docs/cloudbees-platform/latest/aspm/implicit-security-analysis[Code and binary security analysis].

== Scanner information

The Snyk Code scanner architectural components are:

* Snyk CLI: The command-line interface that performs the scanning.
* Snyk Code Engine: Analyzes source code using semantic analysis and machine learning.
* Snyk Knowledge Base: Contains information about security vulnerabilities and coding best practices.
* Snyk API: Communicates scan results to the Snyk platform for centralized management.

The scanning process is as follows:

. The Snyk Code scanner identifies source code files in your repository.
. Source code is analyzed using semantic code analysis techniques.
. Security vulnerabilities and code quality issues are identified based on Snyk's security knowledge base.
. Results are reported with severity levels, detailed descriptions, and remediation guidance.
. The scan results are uploaded to the Snyk platform (if configured).
. Results are made available as actionable outputs for quality gates and downstream workflow steps.

NOTE: For more information about Snyk Code, refer to the link:https://docs.snyk.io/products/snyk-code[Snyk Code documentation].

== Inputs

[cols="2a,1a,1a,3a",options="header"]
.Input details
|===

| Input name
| Data type
| Required?
| Description

| `snyk-token`
| String
| Yes
| The Snyk API token for authentication.

| `org-id`
| String
| Yes
| The Snyk organization ID.

| `ref`
| String
| No
| Specify the ref to be checked out and scanned.

| `workspace-dir`
| String
| No
| The file path of the code to be scanned.

|===

== Outputs

[cols="2a,1a,4a",options="header"]
.Output details
|===

| Output name
| Data type
| Description

| `critical-count`
| String
| The number of *Critical* severity issues discovered during the scan.

| `very-high-count`
| String
| The number of *Very High* severity issues discovered during the scan.

| `high-count`
| String
| The number of *High* severity issues discovered during the scan.

| `medium-count`
| String
| The number of *Medium* severity issues discovered during the scan.

| `low-count`
| String
| The number of *Low* severity issues discovered during the scan.

| `policy-subject`
| JSON
| A JSON value containing details about the vulnerability scan summary and details.

|===

== Usage examples

=== Basic usage

The following is a basic usage example for this action:

[source,yaml]
----

      - name: Scan with Snyk Code
        uses: cloudbees-io/snyk-sast-plugin@v1
        with:
          snyk-token: ${{ secrets.SNYK_TOKEN }}
          org-id: ${{ vars.SNYK_ORG_ID }}
          ref: main

----

=== Scan a Node.js application with Snyk Code

The following CloudBees platform workflow example scans a Node.js application with Snyk Code.

[source, yaml,role="default-expanded"]
----

name: snyk-code-scan
kind: workflow
apiVersion: automation.cloudbees.io/v1alpha1

on:
  push:
    branches:
      - main

permissions:
  scm-token-own: read
  scm-token-org: read
  id-token: write

jobs:
  snyk-code-scan:
    steps:
      - name: Check out Node.js source code
        uses: cloudbees-io/checkout@v1

      - name: Snyk Code scan on Node.js application
        uses: cloudbees-io/snyk-sast-plugin@v1
        with:
          snyk-token: ${{ secrets.SNYK_TOKEN }}
          org-id: ${{ vars.SNYK_ORG_ID }}
          ref: main

----

=== Using the action output

Access the output values in downstream steps and jobs using the `outputs` link:https://docs.cloudbees.com/docs/cloudbees-platform/latest/dsl-syntax/contexts[context].

Use the output in your workflow as follows, where <action_step_ID> is the action step ID, and <severity> is an output parameter name, such as `critical-count`:

[source,yaml]
----
${{steps.<action_step_ID>.outputs.<severity>}}
----

The following example uses the action output in a downstream step of the same job:

[source,yaml,role="default-expanded"]
----

name: my-workflow
kind: workflow
apiVersion: automation.cloudbees.io/v1alpha1

on:
  push:
    branches:
      - main

permissions:
  scm-token-own: read
  scm-token-org: read
  id-token: write

jobs:
  snyk-code-scan-job:
    steps:
      - name: check out source code
        uses: cloudbees-io/checkout@v1

      - id: snyk-code-step
        name: snyk code scan
        uses: cloudbees-io/snyk-sast-plugin@v1
        with:
          snyk-token: ${{ secrets.SNYK_TOKEN }}
          org-id: ${{ vars.SNYK_ORG_ID }}
          ref: main

      - name: source dir examine
        uses: docker://golang:1.20.3-alpine3.17
        shell: sh
        run: |
          ls -latR /cloudbees/workspace

      - id: print-outputs-from-snyk-code-step
        name: print outputs from upstream snyk code step
        uses: docker://alpine:latest
        run: |
            #printing all outputs
            echo "Outputs from upstream Snyk Code step:"
            echo "Critical count: ${{steps.snyk-code-step.outputs.critical-count}}"
            echo "Very high count: ${{steps.snyk-code-step.outputs.very-high-count}}"
            echo "High count: ${{steps.snyk-code-step.outputs.high-count}}"
            echo "Medium count: ${{steps.snyk-code-step.outputs.medium-count}}"
            echo "Low count: ${{steps.snyk-code-step.outputs.low-count}}"
            echo "Policy subject: ${{steps.snyk-code-step.outputs.policy-subject}}"


----

The following example uses the action output in a downstream job:

[source,yaml,role="default-expanded"]
----

name: my-workflow
kind: workflow
apiVersion: automation.cloudbees.io/v1alpha1

on:
  push:
    branches:
      - main

permissions:
  scm-token-own: read
  scm-token-org: read
  id-token: write

jobs:
  job1:
    outputs:
      snyk-code-job-output-critical: ${{ steps.snyk-code-step.outputs.critical-count }}
      snyk-code-job-output-very-high: ${{ steps.snyk-code-step.outputs.very-high-count }}
      snyk-code-job-output-high: ${{ steps.snyk-code-step.outputs.high-count }}
      snyk-code-job-output-medium: ${{ steps.snyk-code-step.outputs.medium-count }}
      snyk-code-job-output-low: ${{ steps.snyk-code-step.outputs.low-count }}
      snyk-code-job-output-policy-subject: ${{ steps.snyk-code-step.outputs.policy-subject }}
    steps:
      - name: check out source code
        uses: cloudbees-io/checkout@v1
        with:
          repository: my-gh-repo-org/my-repo
          ref: main
          token: ${{ secrets.GIT_PAT }}

      - id: snyk-code-step
        name: snyk code scan
        uses: cloudbees-io/snyk-sast-plugin@v1
        with:
          snyk-token: ${{ secrets.SNYK_TOKEN }}
          org-id: ${{ vars.SNYK_ORG_ID }}
          ref: main

  job2:
    needs: job1
    steps:
      - id: print-outputs-from-job1
        name: print outputs from upstream job1
        uses: docker://alpine:latest
        run: |
          # Printing all outputs
          echo "Outputs from upstream Snyk Code job:"
          echo "Critical count: ${{ needs.job1.outputs.snyk-code-job-output-critical }}"
          echo "Very high count: ${{ needs.job1.outputs.snyk-code-job-output-very-high }}"
          echo "High count: ${{ needs.job1.outputs.snyk-code-job-output-high }}"
          echo "Medium count: ${{ needs.job1.outputs.snyk-code-job-output-medium }}"
          echo "Low count: ${{ needs.job1.outputs.snyk-code-job-output-low }}"
          echo "Policy subject: ${{ needs.job1.outputs.snyk-code-job-output-policy-subject }}"

----
